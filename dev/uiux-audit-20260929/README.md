# UI／UX 瀏覽器檢查 — 2026-09-29

## 範圍與方法

使用 Codex 內建瀏覽器實際開啟目前 `src/` 經 `dev/server.cjs` 提供的頁面，使用現有 38 位成員資料。檢查桌面 1440×900（另觀察預設 1280×720）、直向 390×844、橫向 844×390 與 667×375。操作包含成員清單、定位、成員詳情、兩人關係查詢、全圖縮放、新增成員表單與新增關係欄位；未提交成員或關係變更。

重要限制：這是桌面瀏覽器調整 viewport 的實測。工具未提供 coarse pointer／手機觸控模擬，因此橫向專用的 `(pointer:coarse)` 分支未完成實測；不能據此宣稱 iPhone／Android 實機橫向有相同缺陷。未測實體鍵盤彈出、瀏海安全區、雙指手勢、正式站 Google 授權及雲端衝突。測試為本機開發模式，不等同已部署靜態站。最初懷疑版本快取，後以獨立 port 4189 及 DOM 腳本清單核對，確認目前模組確實載入，不能將入口差異直接歸因於舊版本。

## 優先處理

### P1-1：清單代別與全圖代別不一致

- 實測：成員清單的陳阿土、林氏為第 1 代；全圖定位到陳阿土時，所在色帶標示第 2 代。陳文彬清單為第 2 代，全圖位於下一層。
- 影響：使用者難以判斷代別是家族輩分、排版層級，還是受待補親屬影響的推定位置。
- 建議：清單與全圖採用一致的代別定義；若圖上實際是排版層級，應改標籤並解釋待補中間代的影響。此處未判定何者為資料上的正確代別。
- 驗收：同一成員在全圖、清單、篩選及兩人比較中的代別意義一致；局部重新編號需明確標示。
- 證據：[清單](desktop-list.png)、[全圖詳情](desktop-detail.png)。

### P1-2：查詢沿用全圖縮放，結果人物極小且被結果卡遮擋

- 重現：390×844 → 點適應畫面，縮到 30% → 所有成員 → 陳阿土 → 查關係 → 選陳文彬 → 查詢。
- 結果：正確顯示「陳文彬為陳阿土的兒子」，但兩人圖仍為 30%，擠在左上角，大部分畫面空白，上方人物被結果卡覆蓋。
- 建議：進入比較時以結果子圖重新計算可用區域，扣除結果卡高度，置中並使用可閱讀比例；退出後還原原全圖視角。
- 驗收：從 30%、100% 或任意平移位置開始查詢，兩個端點均可見且姓名可讀，不被浮層遮住。
- 證據：[直向結果](portrait-query.png)。

### P1-3：低高度、精細指標裝置缺乏緊湊佈局

- 實測：844×390 的桌面指標模式，標題與工具列高 109px，查詢列至 y=170，圖例至 y=335.47，畫布僅剩約 54.53px。667×375 同樣受到圖例與工具列擠壓。
- 建議：主要版面壓縮依可用寬高決定；觸控判斷僅控制手勢與按鈕密度。低高度時圖例預設收合、工具集中到更多選單，為畫布保留明確最低空間。
- 驗收：橫向窄視窗在滑鼠、觸控與混合輸入裝置均保有可用畫布；另補手機 coarse-pointer 真實分支測試。
- 證據：[844×390，桌面指標模式](landscape-pointer-fine.png)。

## 次優先改善

### P2-1：直向新增成員流程過長

390×844 首屏被姓名、所在地、職位、性別、師門次序、手足次序及解說佔滿；重要的「與現有成員的關係」在下方。建議依「姓名／性別 → 親屬關係 → 選填資料」重排，師門、排行與長說明採逐步展開。關係來源及備註可收為進階選填。保留固定儲存列。

證據：[直向表單](portrait-form.png)、[橫向表單](landscape-form.png)。

### P2-2：空白欄位佔用畫布與清單

多張卡片重複「所在地：未填寫」「職位：未填寫」「手足序：未填寫」。手機成員清單也為空白所在地及職位保留整行；390px 寬畫面首屏僅容納約四張清單卡片。建議只顯示已填資訊，缺漏集中在編輯頁提示，清單以姓名、代別和必要識別資訊為主。

### P2-3：桌面圖例預設展開，壓縮主內容

1440×900 中主畫布約從 y=258 才開始，圖例呈現 13 種關係說明。建議預設顯示目前範圍出現的關係或收合為一行；第一次使用另提供簡短導覽。縮放工具未操作時偏淡，建議維持足夠可辨識度。

### P2-4：手機圖示缺乏可見文字

直向首頁使用清單、人像加號、雲端與馬賽克圖示；詳情操作也只剩鉛筆、雙箭頭及加號。雖已有無障礙名稱，觸控使用者無法依靠滑鼠懸停說明。建議為高頻操作保留短文字，低頻操作集中於「更多」；隱藏姓名可使用眼睛圖示搭配狀態文字。

### P2-5：查詢視角與選單識別可以更直接

手機查詢顯示「以誰為稱呼基準」「想知道誰與他的關係」及「A 是 B 的誰」，使用者仍需對照抽象代號。建議在選人後即以姓名顯示完整問句，例如「陳文彬是陳阿土的誰？」。目前選單主要只顯示姓名，可補代別或親屬摘要以協助未來同名成員辨識；本次未建立同名資料驗證。

## 已有且值得保留的設計

- 搜尋式成員選單可選人，關係查詢成功顯示結果。
- 成員清單可定位並開啟詳情。
- 手機表單採全畫面、儲存操作固定底部。
- 未儲存關係表單離開時會要求確認，已實際觸發並捨棄本次空白測試修改。
- 小比例會切换為總覽資訊，減少卡片內容，但仍需改善查詢後的視角切換。
- 本次瀏覽器記錄未出現 error／warn；這不代表全面功能測試通過。

## 建議實作順序

先統一代別定義、修正查詢視角與浮層避讓，再處理低高度佈局；接續整理表單與空白資訊，最後改善圖例及圖示文字。補驗 iOS Safari、Android Chrome 的真實觸控橫向、鍵盤開啟、旋轉後選取狀態，以及多關係／長姓名內容。

# 驗收條件

## Harness 已實作的條件

| ID | 必須成立的條件 | 驗證來源 |
|---|---|---|
| H-01 | 未設定真實 project suites 時不能宣告專案通過 | runner 與 self-tests |
| H-02 | 非零退出碼、零測試、缺少結果、逾時都不通過 | runner 與 self-tests |
| H-03 | 同一次比較的任務、資料清單、環境身份、評估命令與門檻一致 | frozen controls |
| H-04 | 候選必須通過絕對門檻，且沒有超過允許的指標退步 | compare |
| H-05 | 指標無改善且基準已通過時，保留基準 | compare |
| H-06 | 未有可採用比較前，不建立 verified lesson | lesson |
| H-07 | 導入工具預設 dry-run，遇到不同內容的既有檔案整批中止 | install_harness.py |

## 應用程式驗收：導入時完成

尚未設定實際專案驗收。請列出 P-xx 條件，包括觸發輸入、預期輸出、單位、測試資料、必要指標與允許門檻，並在 `harness/config.json` 設定相同機器門檻。

以下是幾何量測專案可參考的條件方向，並非已核定需求：合法邊界可解析、稀疏點不被當成實體坑洞、資料的座標系與深度單位一致、體積相對誤差在約定範圍內、執行時間與記憶體在硬體預算內。其他專案請改成自己的實際需求。

所有門檻都應在看見候選結果之前訂好。基準失敗可以作為修正前證據；候選仍必須通過，且比較所需的數值不能缺漏。只有 pass/fail 的缺陷修正可使用空 metrics：基準 failed → 候選 passed 才算改善；兩者都 passed 則不支持宣稱改進。

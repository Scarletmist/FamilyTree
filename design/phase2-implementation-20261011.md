# 第二階段實作紀錄

日期：2026-10-11。範圍：安全維護與待整理資料工作台。

以下保留第二階段交付時的紀錄。使用者後續要求統一封存／刪除按鈕布局，並移除關係確認狀態；目前工作台為四分類，調整與最新驗證見 [調整紀錄](relationship-simplification-20261011.md)。

## 操作入口與結果

## 資料規則

生命週期仍透過 FamilyApp → FamilyRepository → FamilyCommands／FamilyModel 執行。UI 提交帶預覽的版本，跨分頁／雲端變更不會覆寫；取消、搜尋、篩選及開啟預覽都不寫入族譜。

還原預設勾選原關係與群組。對象已刪除、群組更換類型／anchor、排行被占用或其他領域衝突會阻止提交；使用者可取消勾選關係、群組，或明確將舊手足／師門數字排行改為未知，再重新預覽。成員 ID 已占用不能覆蓋。刪除影響也包含推導路徑會消失的後代，不只列出直接鄰接人物。

封存不是死亡狀態。親屬記錄與推導保留，必要的畫布／查詢銜接標示已封存；獨立封存成員不出現在一般全圖，從封存清單選取時可查看。新增關係選單預設排除封存人物；編輯已存在的封存對象關係時保留原選項，避免無意丟失記錄。排行群組的既有封存引用同樣保留。

地圖的有效位置與定位排程使用 `FamilyLocation.locatable()`，資料驗證仍使用原本的所在地／隱私規則，防止封存時丟失 geocode 或手動座標。若同地點仍有未封存成員，進行中的共用查詢會繼續；全部不再符合資格時以 AbortController 取消。事後寫入再檢查當前資料。解除封存可沿用有效座標，缺少或過期時重新排程。

刪除不建立新的直接關係。不存在的選取與詳情導覽會清理，查詢重新計算；最近查看排除刪除與封存人物。舊編輯表單檢視最新資料發現成員已不存在時，保留輸入、顯示說明並停用儲存。

## 工作台

- 未設定關係：檢查完整資料的入向與出向直接關係，提供編輯與新增親屬。
- 待確認關係：正反向穩定鍵去重，顯示來源／說明，開啟原 pending 記錄編輯。
- 待補親屬：沿用 intermediatePlans／slotId 與忽略機制，提供補登與忽略。
- 待處理定位：查無、同名候選、未查詢與查詢失敗的原因，連到現有地點修正。
- 疑似重複成員：姓名 NFKC、空白及大小寫正規化後產生候選，顯示所在地證據與不同 ID，預填現有合併比較；不自動合併。

`family-maintenance.js` 為純衍生資料模組；`family-maintenance-ui.js` 與 `family-maintenance.css` 負責操作介面。問題清單不另存入 JSON；保留的是既有忽略決定。編輯／合併／地點修正使用堆疊模態對話框，完成或取消後回到工作台，更新問題與計數而保留分類、搜尋和可保留的捲動位置。

## 驗證

全量 Node 測試 202 項通過；第一階段與第二階段、關係／合併／模擬雲端、地圖工作區、地點修正、背景定位及靜態儲存的相關瀏覽器測試通過。靜態建置與 `git diff --check` 通過。

- 新增純資料測試涵蓋去重、來源、共用槽、忽略、封存／隱私排除、疑似重複、保留座標、還原數字排行、推導影響及進行中查詢取消。
- `tests/browser-phase2.cjs` 在正式靜態 IndexedDB 與開發 API 各跑桌面 1440px、手機尺寸 390px，涵蓋正式入口、取消不寫入、封存篩選、查詢銜接、過期刪除、保留舊表單輸入、還原群組衝突、重新載入、五類工作台及處理返回。
- 回歸包含第一階段、成員關係／合併／模擬雲端、成員地圖、地點修正及背景定位流程。
- 建置使用 `node dev/build.cjs`，與 `npm run build` 的程式相同；不包含示範族譜。

新增瀏覽器測試可用 `npm run test:phase2:browser` 或 `node tests/browser-phase2.cjs` 執行；Playwright 的套件與瀏覽器路徑可透過既有環境變數指定。

測試操作的是隔離的測試資料與瀏覽器 context。外部定位與圖磚使用模擬回應，未操作真實 Drive 帳號。手機高度、輸入與對話框可由程式及尺寸模擬驗證；安全區、實際鍵盤及觸控感受仍留待 iOS／Android 實機整合驗收。

# 族譜系統調整實作計畫

日期：2026-10-11。狀態：規劃完成，尚未實作。

本計畫涵蓋使用者選定的三項功能與五項介面調整。雲端衝突的範圍已確認：改善結構化差異呈現，保留現有整份本機／Google Drive 版本選擇；成員合併保留現有逐欄選擇與確認流程。

## 1. 範圍與實作原則

| 項目 | Before（目前） | After（本次目標） |
| --- | --- | --- |
| 成員封存與安全刪除 | 新增、修改、合併；沒有獨立封存或刪除流程 | 封存／解除封存、刪除影響預覽、可還原回收區 |
| 待整理資料工作台 | 未設定關係、待補親屬、待確認與定位狀態分散 | 集中分類、計數、搜尋、處理入口及更新後的結果 |
| 可閱讀的族譜輸出 | JSON 備份 | SVG 下載、列印版與瀏覽器另存 PDF |
| 統一關係可信度提示 | 直接／推導、待確認及來源分散呈現 | 共用來源與確認狀態規則，畫布、詳情、查詢及輸出一致 |
| 結構化差異比較 | 文字條列差異 | 按成員分組的欄位／關係比較，明確顯示操作後果 |
| 新增關係提早呈現方向 | 選擇完成後提供雙向稱謂 | 選擇過程就顯示完整姓名句子、角色方向與快捷選項 |
| 手機版精簡詳情首屏 | 導覽列與人物區重複姓名，首屏空間分散 | 單一身分區、固定高頻操作及更直接的親屬摘要 |
| 增加全圖導覽 | 拖曳、縮放、適應畫面與清單定位 | 可收合縮略圖、可視範圍框與快速定位 |

沿用純靜態部署與本機 IndexedDB 架構。所有資料操作經 FamilyApp → FamilyRepository → FamilyCommands／FamilyModel 執行，持續使用同一交易完成版本檢查、資料寫入、復原紀錄及同步 dirty 標記。開發 API adapter 同步支援新增命令。

第一版不加入雲端逐欄合併、多人協作、批次永久清除或新的資料匯入格式。手機操作維持現有瀏覽／收合／完整閱讀模式與手勢政策。

## 2. 共用資料與模組設計

### 2.1 成員生命週期與資料格式

建議將本次格式提升為 schemaVersion 3。新版可載入 v2，將資料遷移到 v3；遷移前保留原始備份，交易成功後才採用新版本。封存與回收區會影響資料語意，使用新版本號可以讓舊程式明確拒絕不支援的資料，避免誤編輯。

- 在成員上增加選填 `archive`，包含封存時間及選填原因；不存在代表正常成員。
- 根物件增加選填 `recycleBin`，保存刪除成員本身、原入向／出向關係、排行群組引用與必要的待補忽略紀錄。
- 回收資料保留原成員 ID、刪除時間與還原所需資訊。衍生的 `inferredRelationships` 在還原後重新計算。
- 封存仍保留成員與親屬關係，必要銜接人物在畫布／查詢中顯示封存標示；一般清單、關係對象選單、地圖及待整理計數預設排除，可透過明確入口查看。
- 封存不是死亡狀態。封存期間保留所在地與已定位資料，但停止地圖顯示及背景查詢；解除封存後再檢查定位是否仍適用。
- 刪除移出現有成員集合並移至回收區，不能繼續作為親屬推導的依據。
- JSON 備份及 Drive 同步保留封存與回收資料；SVG／列印版預設排除回收資料，封存資料依輸出範圍處理。

建議新增純資料模組 `family-lifecycle.js`，集中管理可見性、刪除影響與還原預覽，避免各頁面各自判斷成員狀態。

### 2.2 關係來源與確認狀態

將「如何得到這筆關係」與「是否明確確認」分成兩個維度，避免把直接記錄當成已確認，也避免把推導一律當成不可信。

| 維度 | 顯示規則 |
| --- | --- |
| 來源方式 | 直接記錄／由既有關係推導 |
| 直接關係確認狀態 | `confirmed` → 已確認；`pending` → 待確認；未填 → 未標記 |
| 推導關係的確認提示 | 依目前展示的證據路徑彙整：含待確認則「依據待確認」；全為明確確認則「依據已確認」；其他則「依據未完整標記」 |
| 證據 | 顯示涉及的成員、關係、來源與說明，並提供原記錄的編輯入口 |

現有模型已接受 confirmed／pending；表單目前只保存 pending。新表單須保留使用者明確選擇的 confirmed，新增關係預設未標記，舊資料不補上 confirmed。

建議新增 `relationship-evidence.js`，以穩定、雙向正規化的關係鍵對應原記錄和推導證據。共用筆畫可能包含不同關係的證據，提示須能追溯每一段，不把單一狀態套用到不相關的整組關係。

### 2.3 結構化差異資料

建議新增純資料模組 `family-diff.js`，比較結果是結構化資料，不從既有中文差異字串反向解析。

每個差異項目包含實體類型、成員／關係／群組的穩定鍵、欄位、舊值、新值、操作種類及影響對象。比較涵蓋成員欄位、關係 metadata、排行群組、家族名稱、封存、回收區，以及未識別的擴充欄位。

反向存放的同一關係須先正規化，避免只改了資料存放方向就顯示成新增／移除。未標記和明確 confirmed 保留差異。背景定位、定位裝置等系統資料另分組收合，但仍可查看。

保留 `FamilyModel.dataDifferences()` 的文字輸出相容介面，改由結構化資料格式化，降低既有測試與使用者提示的變動範圍。

### 2.4 共用畫布幾何

縮略圖與輸出共用同一份節點位置、連線路徑、代別帶及實際邊界資料。從目前 `family-tree.js` 的排版／繪製流程抽出必要的場景資料，沿用 `family-tree-layout.mjs`、connector routing、label layout 與 renderer 的既有規則。

建議新增 `family-tree-scene.mjs` 提供目前場景與指定範圍的完整資訊場景；viewport controller 提供可視範圍與視角變化事件。縮略圖只是導覽，SVG／列印使用完整資訊輸出，不能把低比例總覽截圖當成正式輸出。

## 3. 八項調整的具體實作

### A. 成員封存與安全刪除

入口放在成員詳情「更多」；所有成員提供封存成員與回收區入口。

1. 封存前說明會影響的清單、地圖與選單。封存和解除封存各是一項可復原操作。
2. 刪除前列出成員、所有相關直接關係、排行群組與銜接影響。明確說明只刪除此成員，不連帶刪除親屬、不自動把兩端接成新的親屬關係。
3. 同一交易移除成員、清理其他人的引用、調整群組引用、保存回收資料並重新推導。群組失去 anchor 時改為未指定；空群組可保留供後續整理。
4. 已開啟的表單、詳情、查詢、最近查看、地圖選取與視角紀錄需處理已不存在的成員。背景定位寫入須重新檢查目前的成員狀態。
5. 回收區提供搜尋、刪除時間、影響摘要及還原。還原預覽重新驗證成員 ID、關係對象、群組與排行，不用舊整份快照覆蓋較新的族譜。
6. 無衝突時完整還原；若對象已不存在或排行／關係已改變，列出無法原樣還原的項目，讓使用者明確選擇可還原內容後再驗證。取消不寫入資料。
7. 第一版不自動到期清除回收區。介面說明「移至回收區」仍會保留在備份與同步資料中。

驗收：封存可解除；刪除及還原可復原；沒有失效的成員引用；刪除不憑空建立關係；跨分頁版本變更會阻止過期預覽提交；重新載入、JSON 往返與模擬 Drive 同步均保留狀態。

### B. 待整理資料工作台

在更多功能提供「待整理資料」入口，使用桌面工作面板與手機全畫面清單。初版分類如下：

| 分類 | 判斷與操作 |
| --- | --- |
| 未設定關係 | 沒有入向或出向直接關係；開啟成員編輯／新增親屬 |
| 待確認關係 | 以直接記錄的 pending 關係為單位；查看來源後編輯確認狀態 |
| 待補親屬 | 沿用 `intermediatePlans()` 與 `slotId` 去重；補入親屬或沿用既有忽略機制 |
| 待處理定位 | 顯示查無、同名候選、查詢失敗或待查詢等原因；連到目前地圖修正流程 |
| 疑似重複成員 | 以姓名正規化及所在地等訊號產生候選，說明理由；查看雙方後進入既有合併流程 |

問題清單由目前資料衍生，不另外保存過期的問題結果。僅保存原本已有的忽略決定。待確認推導路徑指向原始 pending 記錄，不為每條衍生關係重複建立待辦。

每列顯示成員、原因及主要操作，支援分類、搜尋與返回原位置。處理後即時更新計數。封存、私人地圖排除及單純未填選填欄位不算需要處理的錯誤。

驗收：反向關係與待補共用槽不重複計數；地圖隱私排除不是待定位錯誤；疑似重複不自動合併；完成修正後項目消失；取消／返回保留分類、搜尋及捲動。

### C. 可閱讀的族譜輸出

新增「輸出族譜圖」，與原 JSON 備份匯出分開標示。初版提供 SVG 下載及列印預覽；PDF 由瀏覽器列印對話框另存。

- 範圍：全族譜、目前顯示範圍、目前兩人關係路徑。必要的銜接人物保留並標示，不能因略過人物而畫出不存在的直連關係。
- 內容：家族名稱、代別、姓名、關係圖例、可信度標示；所在地、職位與來源附錄可選。
- 封存預設不作為一般輸出成員，必要銜接與「包含封存成員」範圍需明確標示。回收資料完全不參與圖形輸出。
- 尊重目前姓名隱藏狀態並在預覽中明示；被隱藏的真實姓名不能藏在 SVG title、屬性、註解或附錄中。
- SVG 使用可攜的向量圖形與文字，包含必要樣式／marker，避免依賴原網頁外部 CSS 或以 foreignObject 作為主要文字渲染。
- 列印提供 A4／A3、直向／橫向及跨頁模式。初始正文目標至少 12pt；圖太大時引導跨頁或調整範圍，不能只縮成不可讀的小字。
- 跨頁採頁碼、位置索引、接續連線與適度重疊，優先避免切斷人物卡。預覽能看見裁切與接續範圍。
- 以固定資料版本產生輸出；預覽後資料若更新，提示重新產生，避免看到一版卻輸出另一版。

驗收：中文與長姓名可讀；關係線與代別和畫布一致；一般姓名、隱藏姓名、封存及空族譜皆有正確結果；SVG 在獨立瀏覽器頁面可開啟；PDF 實際另存後逐頁檢查，沒有遺漏人物、標籤或連線。

### D. 統一關係可信度提示

使用第 2.2 節的共用規則，套用到成員詳情、關係依據、查詢摘要／完整路徑、表單與輸出圖例。畫布採精簡標記，點擊或聚焦可查看完整證據。

不以顏色單獨區分。保留既有關係類型的實線、虛線與箭頭意義，可信度另用文字／圖示，避免和收養、過繼等線型衝突。低縮放比例僅保留必要警示，詳細內容在選取後查看。

驗收：同一關係跨介面提示一致；直接但 pending、直接未標記、已確認證據推導、含 pending 證據推導分別正確；編輯原始證據後立即更新；鍵盤與觸控均可查看提示。

### E. 衝突與成員合併的結構化差異比較

以 `family-diff.js` 供應資料，新增共用 `family-diff-view.js`。先接雲端衝突與成員合併，再沿用至既有匯入／表單更新差異預覽。

- 雲端比較使用「此裝置／Google Drive」並列；成員合併使用「目前／合併後」並列。
- 頂部先顯示新增、移除、修改的成員和關係數。刪除、封存、關係變更優先展示。
- 按成員分組，欄位顯示名稱、舊值、新值；關係顯示完整姓名方向、類型與確認狀態。長備註、來源與系統資料可展開。
- 支援只看差異、分類與成員搜尋。桌面左右欄，手機同一項目的兩個值上下排列。
- 雲端仍選整份版本。按鈕明確說明是「以此裝置覆蓋雲端」或「以 Google Drive 取代此裝置」，不出現逐欄雲端合併入口。
- 成員合併保留現有欄位選擇，改動選項後重新產生結果預覽。自我關係、互相矛盾的 metadata／排行仍阻止提交。
- 保留提交前再次檢查本機與遠端版本的機制。

驗收：反向存放不產生假差異；同名以 ID 對應；擴充欄位不被靜默省略；回收／封存變更可見；手機無水平捲動需求；取消不寫入；模擬同步結果維持原整份選擇語意。

### F. 新增關係提早呈現方向

在現有關係列改為完整句子，例如「陳文彬是陳阿土的［子女］」。尚未填新成員姓名時使用「新成員」，填寫或修改姓名時即時更新句子。

常用父母／子女／配偶作為快捷選項，其餘關係保留原完整選單；快捷選項只是設定目前關係，不另存第二套資料。不同方向仍使用原本 parent／child 等資料語意。

保留雙向稱謂預覽；選擇前的句子與儲存後的關係保持一致。從「新增親屬」、待補親屬與反向編輯進入時，既有預帶關係、來源、確認狀態、長幼及排行資料不丟失。

驗收：父母／子女、祖孫、師徒、配偶、手足方向一致；改姓名和對象即時更新；新建、編輯、草稿恢復與預帶流程全部通過；不因 UI 文案改變而顛倒資料方向。

### G. 手機版精簡詳情首屏

合併導覽列與人物區的重複姓名。保留一組姓名、代別及封存標示；返回清單、返回前一位、關閉、展開閱讀等操作仍可使用。

高頻操作固定為「編輯」「查關係」「更多」，其餘留在更多。移除首屏非必要的重複身分資訊，顯示目前已開啟的親屬摘要，保留按成員記住捲動位置及群組展開狀態。

沿用現有面板三種模式、拖曳中斷、焦點管理與返回行為。版面依可用寬高調整，滑鼠／觸控依能力決定；處理鍵盤、瀏覽器工具列和 safe-area，不限制使用者縮放。

驗收：390×844、360×640、844×390 與桌面布局；姓名長達上限時操作不被擠掉；瀏覽模式至少可見一組親屬內容或明確空狀態；切成員、返回、收合／完整閱讀維持原流程。iOS Safari／Android Chrome 實機另外驗證旋轉、鍵盤與安全區。

### H. 增加全圖導覽

新增「全圖導覽」切換入口，桌面提供小型浮動縮略圖，手機預設收合。縮略圖顯示節點與簡化連線，不重複全部姓名，標示目前選取人物及可視範圍框。

點擊縮略圖定位、拖曳可視框平移；提供鍵盤可操作的回全圖／回選取成員控制。畫布滾動與縮放僅更新視窗框，資料／範圍改變才重新生成縮略圖場景。

目前範圍和兩人比較模式分別呈現對應場景，標示「全族譜／目前範圍／比較路徑」。結束比較沿用目前的視角還原行為。

可視框以 viewport controller 的實際可用區域計算，考慮成員清單、詳情面板與查詢結果遮蔽。手機完整閱讀、鍵盤及對話框開啟時暫時收起導覽，避免重疊。縮略圖的點擊／拖曳不觸發底層畫布操作。

驗收：最低／最高縮放、不同 scroll 位置、面板開合與旋轉後可視框正確；點擊和拖曳可定位；退出比較還原原視角；縮略圖不產生第二套族譜或每次滾動整圖重繪。以 50／200／1000 位合成資料記錄生成與互動效能，據實決定大型資料的簡化門檻。

## 6. 驗證與完成定義

目前基準為 178 項 Node 測試通過；先前瀏覽器檢視使用本機開發模式及手機尺寸模擬，不代表靜態 IndexedDB、真實 OAuth 或手機硬體已全部驗證。

實作後須完成：

1. 純資料測試：v2／v3 遷移、封存／刪除／還原、引用清理、推導再計算、關係鍵、差異、待辦去重與字級／跨頁幾何。
2. 真正瀏覽器流程：新增／編輯／草稿、封存與回收區、工作台返回、衝突整份選擇、成員合併、可信度、手機首屏、縮略圖與輸出。
3. 靜態模式：IndexedDB 交易、重載、跨分頁版本、儲存失敗、復原、JSON 匯入匯出及資料遷移備份；不能只測 dev API。
4. 模擬 Drive：封存／回收區往返、pending／confirmed 保留、過期差異預覽被拒絕，確認取消流程不寫入雲端。
5. 輸出視覺檢查：長姓名、複雜婚姻、親生／收養／過繼、待補中間代、封存橋接、隱藏姓名及大型跨頁案例；保存並逐頁檢視真正另存的 PDF。
6. 手機實機：iOS Safari 與 Android Chrome 的鍵盤、工具列、安全區、橫向／旋轉、雙指縮放、面板與縮略圖手勢。若當時無設備，明確保留為未完成驗收項目。
7. 全量回歸與建置：`node --test tests/*.test.cjs`、與改動相關的既有 browser suites、新增流程測試、`npm run build`，確認 dist 不含測試族譜與開發資源。

測試重點是資料與操作結果，不為單純文案、低影響樣式增加鏡像式測試。完成標準是八項調整都能從正式入口使用，舊資料可遷移，復原／同步／輸出互相一致，且所有必要驗收項目均有結果。

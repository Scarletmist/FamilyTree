# 族譜 UI Layout 設計提案

日期：2026-09-30。範圍：設計分析與獨立原型；未修改 production source 或族譜資料。

## 分析依據與限制

重新執行 codebase-memory full 索引，並檢查 11 個 UI 來源檔的 coverage。工具仍回報 metadata_changed，因此圖譜僅作導航，實質結論由目前來源的相關程式段及瀏覽器頁面交叉核對。透過本機 HTTP 比對，頁面等於 dev/site-source.cjs 即時展開的來源；CSS、coordinator、詳情、清單工具、查詢與四個畫布模組皆與 src 逐字一致。

目前瀏覽器確認的是本機開發模式、約 918px 寬畫面及人物詳情。9/29 截圖只作歷史背景，不作現況證據。本次沒有宣稱手機實機、Google OAuth、靜態 IndexedDB 路徑或所有功能已回歸驗證。附原型使用獨立示例，不載入使用者族譜、不連接儲存與同步。

## 已有且保留

新版已具備圖例預設收合、畫布空值隱藏、手機短文字與更多操作、表單主要／選填分組、搜尋選单 visualViewport 避讓、查詢 fit／center 與退出還原原視角。這些是設計基礎，不應再當作尚未處理的舊問題。

## 建議方向：安靜、清楚的族譜工作空間

採 Apple Design 的層級、即時回饋與空間一致性，保留家族工具的暖白與酒紅；主要內容使用實色，透明材質只用於短工具浮層。避免把整個畫布做成玻璃背景。

### 1. 桌面工具分成兩層

第一層約 64px：家族名稱與編輯、所有成員、雲端狀態、新增成員、更多。新增成員是主要實色按鈕。匯入、匯出、名稱顯示與低頻設定放在更多，保留明確文字及原有處理程序。雲端狀態應反映真實 disconnected／pending／conflict／error，不能以泛用「已儲存」掩蓋衝突；現有 attention banner 保留。

第二層約 52px：顯示範圍、查詢兩人關係、顯示全部／結束比較、圖例。寬畫面可直接顯示兩個選人欄位；約 960–1199px 建議使用「查詢兩人關係」展開入口，避免目前約 918px 的查詢列換行。這是待驗證的設計斷點，不應直接取代既有 mobile/coarse pointer 判斷。

查詢結果以正常文句呈現「陳文彬是陳阿土的兒子」，旁邊顯示交換、路徑及結束比較。既有方向、路徑與不確定說明保留，完整依據可展開。

### 2. 畫布保留資訊密度，弱化裝飾

世代色帶保留，降低背景飽和度，以清楚的代別標籤維持定位。卡片維持 semantic zoom 不同密度；正常倍率以姓名為主、已填辨識資訊為次，排行仍有入口。卡片半徑 12px、細邊框、極輕陰影；選取採酒紅描邊加淡底色，鍵盤焦點另保留清楚 outline。

第一階段只改顏色、字重、邊框與留白，不改卡片 width/min-height/generation-gap 等幾何 token。之後若改尺寸，需一起檢查 SVG 避讓、加號位置、代別背景與縮放重建。

縮放列維持在畫布下緣且始終可讀；不要將整組控制 opacity 降至 .25。可讓外框與陰影變淡，按鈕文字保持對比。保留百分比、密度、加減與適應範圍。

### 3. 成員詳情：桌面預留空間，手機沿用底部面板

寬度至少約 1200px 時，建議展開的詳情為 320–360px 右側佔位區；只有展開時佔位，收合後釋放畫布。無遮罩，可繼續操作族譜。打開時需以目前選取人物為錨點重新計算 viewport，不能讓 resize 變成重設視角。

中等寬度沿用目前可收合浮卡，避免同時常駐左右側欄。手機沿用 collapsed peek 與展開底部面板；點人物不立即以大面板覆蓋畫布。橫向低高度延續既有橫向策略，依可用高度判斷，不只依 pointer。

詳情標題直接使用姓名，次行放有資料的識別資訊。保留編輯／新增親屬、查關係／定位，以及關係分類数量與收折。關係每列以姓名和稱謂為主，直接設定／推導、待確認、來源說明為次；不刪除語意資訊。

### 4. 清單與表單統一視覺

成員清單保留搜尋、全部／未設定關係、最近查看、代別、定位與管理入口。搜尋和篩選固定於清單頂端；排行群組、合併重複、已忽略待補項目分為管理區，復原保持可發現。不可因精簡版面移除任何管理功能。

表單延续姓名與性別 → 關係 → 選填資料。改善欄位標籤、區塊間距、inline error 與固定儲存列；不重新設計填寫順序或改動驗證。保留草稿、未儲存離開提示及版本衝突流程。

## 建議視覺規格

| 項目 | 初始設計值 |

| 主背景／卡片 | #F7F6F2／#FFFFFF |
| 主文字／次文字 | #26251F／#66645F |
| 品牌色 | #8C3A2B，沿用目前識別 |
| 分隔線 | #E3E1DA |
| 字型 | system-ui、Microsoft JhengHei；中文姓名可保留現有 serif 風格 |
| 字級 | 標題 22–24px、姓名 18px、內容 15–16px、輔助 13px |
| 間距 | 4、8、12、16、24px；文字相關間距使用 rem |
| 圓角 | 控制 8–10px、卡片 12px、panel 16px |
| 觸控 | 高頻按鈕至少 44×44 CSS px；搜尋輸入至少 16px |

中文字距維持接近 0，避免套用英文大標題的負 tracking。所有實際顏色與狀態需檢查對比，不只依賴顏色區分。

## 動態與無障礙

按下立刻有背景回饋，實際 action 仍依既有 click／pointer-up 邏輯。短選單約 120–160ms；詳情開合可用無回彈 spring（response 約 .3–.4），但不得搶走焦點或鎖住操作。這些是設計起點，不是固定完成時間。

畫布平移及縮放沿用現有直接追隨手勢，避免為「Apple 風格」額外加入彈跳。prefers-reduced-motion 改為短淡入或直接切換；reduced-transparency 使用實色；contrast more 增強邊框。dialog 保留焦點限制與返回焦點，非 modal 詳情不加遮罩。

## 實作順序與驗收

1. 視覺 token、字體、邊框、按鈕與縮放可讀性。先保持 DOM 結構與卡片幾何不變。
2. 工具列分組與中寬版型。檢查既有 toolbar 搬移、More、query sheet 對 DOM 的依賴，保留唯一 ID 與原事件綁定。
3. 寬桌面詳情佔位，與 viewport available geometry／anchor 一起實作；這是風險最高的 layout 變更，單獨驗證。
4. 統一清單、表單、查詢結果與狀態視覺。

正式變更驗收涵蓋：新增／編輯／新增親屬／取消與草稿、關係查詢交換與多路徑、退出回復原視角、清單搜尋與管理／復原、JSON 匯入差異與匯出、靜態 IndexedDB 重新載入、同步 pending／conflict／error，以及鍵盤焦點、semantic zoom、連線與加號避讓。

尺寸至少檢查 1440×900、1024×768、918×884、390×844、844×390、667×375；手機補 iOS／Android 實機鍵盤與 pinch。使用既有 Node 與 browser 回歸測試，新增測試只針對新增的佔位與斷點行為。比較操作前後 JSON，驗證純 UI 操作沒有資料修改。

## 原型範圍

ui-layout-prototype.html 提供桌面／手機示意、人物詳情選取、查詢模式與圖例展開。工具管理、資料編輯、完整圖形路由及資料持久化不在原型內；示意尺寸不代表正式 geometry。原型只用於評估層級、留白與視覺方向。

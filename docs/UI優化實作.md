# UI 優化實作清單

日期：2026-10-20。以下對應前次介面盤點的 28 項建議；本次保留現有資料模型、復原、草稿，以及合併／匯入／回收／同步的預覽與確認流程。

| 編號 | Before：原本狀況 | After：本次實作 | Why：改善目的 |
| --- | --- | --- | --- |
| 1 | 開關側欄後卡片重新置中，SVG 留在舊座標。 | 將已量測的畫布寬度固定至下次完整布局；卡片與 SVG 使用相同座標，重繪時重新量測。覆蓋左右、雙側、收合、縮放。 | 避免誤判連線對象，保留既有視角與人物定位。 |
| 2 | 手機新增親屬藏在更多操作。 | 新增親屬提升至操作列，帶文字；桌面也提供獨立一列的入口。封存與回收留在更多操作。 | 提升建譜效率並區分管理操作。 |
| 3 | 查看成員用鉛筆，使用位置只有勾號。 | 查看改為人物圖示＋「查看成員」；保存改為勾號＋「使用此位置」。 | 讓查看、修正及保存意義清楚。 |
| 4 | 同址套用範圍藏在捲動區底部。 | 範圍選項、目前套用姓名摘要移到固定儲存區旁；可關閉批次套用，展開完整名單與影響說明。 | 儲存前即可確認更新誰；保留原預選範圍與復原能力。 |
| 5 | 排行群組看不到已選成員摘要。 | 固定顯示已選人數、姓名及排行；已選優先、只看已選、姓名／所在地／父母搜尋；說明改為展開閱讀。 | 減少漏選和反覆捲動。 |
| 6 | 合併每個欄位都要選擇，同名和長備註難核對。 | 顯示雙方身分摘要；相同欄位收合，差異以完整內容及單選卡比較；預覽後定位至差異，選項變更立即停用確認。 | 核對差異時更清楚，仍需先預覽才能合併。 |
| 7 | 未設定雲端仍主推同步。 | 空族譜以新增第一位成員為主、匯入次之；雲端可用時才顯示同步入口。 | 讓第一步能實際完成。 |
| 8 | 群組、回收預覽直接顯示 JSON。 | 群組顯示類型、所屬人物、成員與排行；回收顯示姓名、時間及可還原參照數量；原始資料放入進階展開。差異摘要涵蓋所有類別。 | 合併、匯入、回收和同步時可理解影響。 |
| 9 | 畫布底部顯示技術性備份說明。 | 正常狀態不再顯示長篇備份提示；保留簡短儲存狀態、獨立同步提示。備份用途移至更多功能，備份失敗仍提示。 | 減少遮擋並區分儲存與同步。 |
| 10 | 更多功能清單長，輸出與設定難找。 | 備份／同步／輸出優先；分類可收合，加入功能搜尋；各操作保持原入口與狀態。 | 可以分類掃讀或直接搜尋。 |
| 11 | 家庭篩選叫「所有關係」。 | 改為「家庭分支／全族譜」，篩選時提供返回全族譜按鈕。 | 名稱符合實際篩選範圍。 |
| 12 | 全域與人物查詢都叫查關係。 | 全域改為「查兩人關係」，人物改為「以此人查詢」，保留預填稱呼基準。 | 讓查詢起點明確。 |
| 13 | 關係來源直接展開，其他路徑在長內容後方。 | 先列稱謂與節點；路徑切換移到來源之前，每段依據與原始記錄按需展開，重複依據不再重列。 | 先理解結論，再核對證據。 |
| 14 | 封存瀏覽和封存管理入口重複。 | 清單保留已封存篩選，移除旁邊重複管理入口；回收與待整理標為資料管理；維持姓名／補充資料兩行，整列可操作。 | 減少入口歧義並保留原觸控範圍。 |
| 15 | 排行所屬人物及合併使用原生長選單。 | 共用可搜尋選人元件；以代別、父母、所在地、職位及同名記錄序號區分，套用至關係表單與查詢。快取標籤供大量成員使用。 | 保持一致選人方式，避免依賴原始 ID。 |
| 16 | 單一人物的句子仍稱父母或子女；新增關係混在一起。 | 表單及依據依已知性別使用父親／母親、兒子／女兒；新增入口分親屬、契親、師門。 | 讓關係方向及稱呼自然易懂。 |
| 17 | 手機詳情多個純圖示難理解。 | 返回、閱讀／返回瀏覽、收合與關閉帶短標籤；閱讀狀態同步文字。 | 保留原有手勢與模式，降低記憶負擔。 |
| 18 | 人物資料與大量分類需要長距離捲動。 | 手機提供個人摘要、資料與備註跳轉、各關係分類與人數導覽；跳轉會展開該分類。保留閱讀位置和收合狀態。 | 快速找到個人資訊及特定關係。 |
| 19 | 推導徽章與畫布 i 觸控範圍偏小。 | 手機推導按鈕至少 44px；畫布 i 使用隨縮放調整的透明觸控範圍，維持至少 44px 螢幕範圍。 | 保持精簡圖示並改善點選。 |
| 20 | i、＋及標籤同時出現，意義不明。 | 一次性操作說明解釋 i 與＋；一般來源入口降低視覺強度，選取、聚焦及查詢時突出。 | 保留來源追溯，同時降低圖面干擾。 |
| 21 | 待整理清單很長，更新資料語意不清。 | 固定搜尋／分類／計數；任務依類別可收合，搜尋會展開符合分類；使用「核對重複成員」「補親屬」「重新整理」。 | 提升連續整理效率。 |
| 22 | 少量差異仍顯示完整篩選列。 | 8 項以下先收合進階搜尋及篩選；匯入更新按鈕改為「重新讀取並比對」。 | 將注意力放在變更內容。 |
| 23 | 輸出預覽只見局部，設定改後狀態不明。 | 預設適應範圍，可切原尺寸及逐頁預覽；設定旁顯示待更新狀態，舊預覽標示並淡化；改名下載向量圖（SVG）。 | 容易核對紙張與全圖，保留手動更新及過期輸出保護。 |
| 24 | 初始畫面缺乏方向感。 | 顯示「看全圖」、操作說明及「定位人物」；教學只首次展開，可隨時再看。保留最近查看與原視角恢復。 | 提供方向感，避免一律縮成難讀的小圖。 |
| 25 | 必要說明偏淡偏小，新增群組也顯示移除。 | 次要文字加深，必要表單說明 13px；管理按鈕採共同主次／危險樣式，新群組隱藏移除；失敗時保留原停用狀態。 | 提高可讀性與操作一致性。 |
| 26 | 橫向群組需先捲過設定；空內容略超界。 | 橫向群組使用設定／成員雙欄；手機管理視窗統一留白，空內容使用獨立置中布局。 | 利用橫向空間並修正裁切。 |
| 27 | 長家族名稱被截斷，小圖示難懂。 | 點家族名稱可讀完整名稱；手機姓名顯示／地圖與看全圖帶短標籤，保留無障礙名稱。 | 兼顧窄螢幕與首次使用。 |
| 28 | 雲端衝突本機時間固定未提供。 | 顯示實際儲存時間；缺少時間時明確說明並引導查看內容差異，列出差異數。保留兩個取代方向及明確版本確認。 | 協助依內容選版，避免時間造成誤判。 |

## 驗證

- 單元測試 256 項通過。
- 新增 UI 流程回歸：API／瀏覽器儲存 × 1440×1000、390×844、360×640、844×390，驗證側欄／縮放的端點、人物詳情、排行保存與復原、合併差異與預覽失效、可讀差異、輸出頁面與過期保護。
- 上述流程也以 WebKit 引擎驗證；不視為 iOS Chrome 實機測試。
- 重新檢視桌面、手機直向、小螢幕與橫向共 73 個介面狀態。
- 既有按鈕布局測試 12 種尺寸通過，包含 320px 窄螢幕及手機橫向。
- 既有連線端點、避障、標籤、排行連線、地圖工作區、資料整理、合併／匯入／雲端衝突、導覽與輸出測試通過。
- 靜態建置及發布檢查通過；不含開發用族譜資料。

手機畫面使用瀏覽器模擬；iOS Chrome 實機的軟鍵盤、網址列收合、安全區與慣性捲動仍需實機確認。地圖及雲端採測試回應，沒有對使用者的真實族譜或 Google 帳號寫入。

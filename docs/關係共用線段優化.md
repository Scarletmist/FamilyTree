# 關係共用線段優化

## 問題原因

既有程式能辨識部分可共線的關係，但各條連線仍各自選擇卡片出口與路徑，最後才合併重疊線段。在沒有待補父母節點的直接接線情況下，當 C 位於 A、B 中間時，C–A 與 C–B 會各自使用左、右出口，即使已歸為同組，也沒有實際重疊的線段可合併。

此外，原本依關係資料的先後順序逐條分組，較小的分組可能先占用連線，拆散原本能合併的較大分支。師兄弟姊妹的共線判斷也只驗證每兩條連線，未要求整組具有同一位共同師父。

## 調整項目

| 項目 | 調整後行為 |
| --- | --- |
| 堂親 | 另一側有親生手足依據時，共用同一成員的出口，再向各成員分支。堂哥、堂弟的長幼差異與記錄方向不影響共線判斷。 |
| 表親 | 維持獨立連線。即使另一側為親生手足，也不能僅憑表親關係確定父系或母系的共同分支。 |
| 親生手足 | 整組必須具有至少一位相同的親生父母；排行群組本身不作為親生手足的證據。 |
| 師兄弟姊妹 | 整組必須具有至少一位相同師父，避免僅有兩兩重疊的師承被誤合併。 |
| 師徒 | 保留以同一位師父為根的分支。若親屬關係使徒弟位於師父上、下不同代，仍依實際代別使用上、下出口。 |
| 分組順序 | 先列出有依據的候選分組，再優先採用成員較多的分組；同大小時使用穩定排序，減少資料先後與記錄方向造成的差異。 |
| 同代共用出口 | 有共線依據的同代分支統一使用上方出口與整列共同的路由高度，避免成員位於兩側或卡片高度變動時拆成不同出口。單獨連線保留原有就近接線方式。 |
| 重疊與選取 | 共用部分只繪製一次；共用主幹保留所有相關成員，末端分支保留各自成員，點選時仍能區分明亮主幹與淡化分支。 |
| 待補中間關係 | 保留原有「＋」節點與補齊親生父母的表單。共線後仍可點選；同一待補節點仍只呈現一次。 |
| 顯示條件 | 一般連線與僅於詳細關係顯示的連線分組處理；手動與推導連線共用的部分維持顯示，純推導分支仍遵守原有顯示設定。 |

只調整顯示分組與路由，不更動儲存的親屬關係、長幼或代別。已能透過真實父母關係呈現的堂表親，仍使用原本的祖先與親子連線。

## 驗證

- 262 項單元測試通過，新增涵蓋反向記錄、長幼差異、24 種資料排列、較大分組優先、共同師父驗證、表親不可共線與詳細關係顯示邊界。
- 新增 `tests/browser-peer-sharing.cjs`：13 種案例，涵蓋有／無待補父母、共同成員位於中間或兩側、長卡片、手動與推導混合、表親、親生手足、師門排行及上下不同代的師徒。待補案例另驗證「＋」數量、與線段相接、開啟正確成員的補親生父母表單，以及取消後保留待補節點。
- Chromium 與 WebKit 各驗證 API／靜態儲存模式及 1440、390、844 像素畫面，共 156 組案例。檢查出口數量、分支選取、無重複筆畫、無穿越卡片、線段不超出畫布與資料未被修改。
- 既有連線避障、卡片端點、共線及標籤回歸測試通過。

WebKit 驗證為桌面上的瀏覽器引擎測試，未宣稱已在實體 iPhone 的 Chrome 上驗證。

回歸入口：`npm test`、`npm run test:routing:browser`。瀏覽器測試需可使用的 Playwright 與瀏覽器；可透過 `PLAYWRIGHT_BROWSER=webkit` 執行新增測試的 WebKit 版本。

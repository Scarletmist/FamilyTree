# 專案詞彙

族譜領域的核心概念以中文為正規用語。規格檔以英文規範語句（SHALL/MUST）撰寫，但這些概念沒有能穩定彼此區分的英文對應詞，因此資料層的 `kind` 值與本文件的詞條一律使用中文。

每則詞條包含：**正規用語**、**定義**、**避免使用**、**為何重要**。

親屬關係詞條額外標明**是否承繼房別**——這是本專案最容易出錯的一條界線，四種看起來都像「收養」的關係，有兩種入房、兩種不入房。

---

## 房

- **正規用語**：房
- **定義**：由某位族人開出的宗族分支。房別為巢狀排行路徑，自始祖往下每一代取一個排行序號，第一層以「房」、第二層以「支」、第三層以「派」命名，第四層以後以連字號接阿拉伯數字。
- **避免使用**：branch、house、lineage 作為單獨標籤；「家系」「支派」作為同義詞混用
- **為何重要**：房別完全由譜系推導，不儲存於資料中。把它當成一個可自由填寫的欄位，會產生與譜系互相矛盾的第二個事實來源。

## 親生

- **正規用語**：親生
- **是否承繼房別**：是
- **定義**：由該婚姻所出的子女。
- **避免使用**：biological、natural child
- **為何重要**：親生在本模型中不是結構上的特例，而是五種 `kind` 之一。舊模型把親生記在 `unions[].children`、其他記在別處，造成每新增一種關係就要多一個陣列。

## 過繼

- **正規用語**：過繼
- **是否承繼房別**：是
- **定義**：同宗之內將子嗣轉入另一房承嗣，常見於無子者。過繼者參與該房子女的排行，並因此改變其他子女的排行序號。
- **避免使用**：adoption、adopted son
- **為何重要**：過繼的目的正是取得宗族身分，因此必須承繼房別。與「養子女」的差別在於過繼發生在同宗之內。

## 養子女

- **正規用語**：養子女
- **是否承繼房別**：是
- **定義**：異姓收養並入譜的子女。
- **避免使用**：adoption、foster child
- **為何重要**：雖為異姓，但入譜即取得宗族身分，因此與過繼同樣承繼房別。用 foster 一詞會誤導為不入譜的暫時安置。

## 義子女

- **正規用語**：義子女
- **是否承繼房別**：否
- **定義**：結義認親，屬社交性質的擬親關係，不入宗族。
- **避免使用**：adoption、sworn child 作為與義兄弟姊妹不加區分的統稱
- **為何重要**：義子女在圖上有連線，但不得取得房別。若誤與過繼、養子女同等處理，會讓非宗族成員憑空取得宗族身分與排行位置。

## 契子女

- **正規用語**：契子女
- **是否承繼房別**：否
- **定義**：認乾親所形成的擬親關係，較義子女更偏向民俗與情誼，不入宗族。
- **避免使用**：adoption、godchild 作為正式親屬關係
- **為何重要**：與義子女同屬不入房的一類，但兩者在民俗上是不同的儀節，資料中分別記錄以免日後無法還原。

## 契手足

- **正規用語**：契手足
- **是否承繼房別**：否
- **定義**：同輩之間結拜所形成的關係。記錄於 `bonds` 而非 `unions` 或 `descents`，因為它既非婚姻、亦非跨代。兩位成員的世代值不要求相同。
- **避免使用**：sworn siblings 與義子女混稱；把契手足塞進 `unions`
- **為何重要**：這是資料模型中第一種既非婚姻、也非親子的關係。若併入 `unions`，`descents.union` 就可能指向一個結構上不該有後代的關係。

---

## adoption（應避免的籠統用語）

- **正規用語**：無——依實際關係改用 `過繼`、`養子女`、`義子女`、`契子女` 其中之一
- **避免使用**：`adoption`、`adopted` 作為單獨的關係標籤
- **為何重要**：本專案早期的資料模型與規格用單一個 `adoption` 指涉一種關係。現在有四種中文關係都可能被翻成這個詞，而它們在「是否承繼房別」上分成兩派——用一個詞涵蓋，等於把宗族身分的判定依據抹平。

| 中文詞 | 意義 | 是否承繼房別 |
| ------ | ---- | ------------ |
| `過繼` | 同宗之內轉入他房承嗣 | 是 |
| `養子女` | 異姓收養並入譜 | 是 |
| `義子女` | 結義認親，不入宗 | 否 |
| `契子女` | 認乾親，不入宗 | 否 |

英文行文中確實需要提及時，寫出具體的中文詞並附一句說明，不要單獨使用 `adoption` 一詞。

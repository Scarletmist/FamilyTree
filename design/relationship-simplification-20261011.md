| 項目 | Before | After |
| --- | --- | --- |
| 詳情「更多」 | 封存與刪除的按鈕結構與既有操作不同 | 定位、封存／解除封存、移至回收區及新增親屬採同一圖示與文字排列、寬度、留白及至少 44px 點擊高度；刪除保留危險操作色 |

| 詳情與查詢 | 確認狀態徽章及逐段警示 | 保留直接記錄／推導提示、原始來源與說明及編輯入口 |
| 畫布 | 驚嘆號、勾號、未標記圓點 | 有來源或說明時顯示資訊圖示；低縮放只保留目前選取關係的資訊入口 |
| 工作台 | 五分類，包含待確認關係 | 四分類：未設定關係、待補親屬、待處理定位、疑似重複成員 |
| 舊確認狀態 | 影響推導、差異及合併 | 保留原始欄位相容，不作為介面狀態或推導限制，也不因不同舊值阻擋合併 |

來源及說明可在新增、編輯、反向編輯與草稿恢復中保留。沒有來源或說明不會產生待辦。原始記錄修改後，開啟的來源視窗即時更新，關閉後恢復焦點。

新關係不新增 `status`；既有 confirmed／pending 在一般編輯、草稿、JSON 及同步往返中保留。合併兩筆相同關係時不把不同舊狀態視為領域衝突，來源、說明、長幼及群組的矛盾仍會阻擋提交。血緣推導依既有類型、親生類別及路徑規則判斷，契手足、同門及非親生親子不會因此成為血緣依據。

封存、刪除影響預覽、版本保護、回收區還原與復原流程維持既有語意。雲端衝突仍選整份版本，結構化關係差異省略舊 `status`，繼續比較來源及說明。

## 後續關係按鈕調整

同一位親屬的來源入口合為一個按鈕，文字只顯示「直接記錄」「推導」或「直接記錄／推導」。共同雙親推導手足時，點擊一次可查看雙方父母的兩條路徑與四筆原始記錄；更新來源後仍完整保留所有依據。

來源及補填按鈕放在同一操作列，共用 plain-button 的字級、邊框、圓角、留白及至少 44px 高度，以 6px 間距排列，窄螢幕自動換行。親屬類別徽章維持獨立一列。

依使用者最後確認，父母資料完整的堂表親維持原本省略額外推導線段的規則；本次調整限於按鈕呈現。

全量 Node 測試 209 項通過，涵蓋多條手足依據與直接／推導混合時的單一入口；靜態建置及 whitespace 檢查通過。修改前索引另存 `before-proof-button-dedup.graph.db.zst`。

`browser-phase3.cjs` 在靜態 IndexedDB／開發 API 與四種尺寸共八個 context 通過，確認雙親依據、更新後無重複、點擊／鍵盤、補填、草稿及手機閱讀流程。檢視桌面、390×844 與 844×390 截圖，來源及補填按鈕的字級、留白、邊框與高度一致。

初次並行驗證曾遇到本機 HTTP 連線重設／載入逾時，分開重跑後通過。幾何檢查改為等待展開完成並直接取得當前 DOM，避免 API 重繪後量測已移除的舊按鈕；保留原本的全部斷言。

## 推導依據改由徽章開啟

依最新要求移除 `plain-button relationship-source-button`，操作列僅保留 `plain-button relationship-missing`。直接記錄沒有此入口；推導使用原徽章列中的可點擊 `relationship-entry__badge`，保留既有「自動辨別」文字，其他推導顯示「推導」。徽章提供提示文字、讀屏名稱及鍵盤焦點，同一位親屬只建立一個入口。

徽章只開啟推導路徑；同一親屬同時存在直接記錄與推導時，不把直接記錄混入徽章內容。雙親推導手足仍可查看兩條路徑及四筆原始親子記錄，原始來源／說明可編輯。更新來源後即時重解依據，關閉後返回新渲染的徽章；若推導已改為直接記錄，徽章消失，原視窗不會轉而顯示直接記錄。

手機徽章保持精簡樣式與 32px 高度，補填按鈕維持 44px。父母完整的堂表親線段規則沿用原本行為。

# Apple 設計原則：介面與操作流程整理

日期：2026-11-03。以現有正式介面為基礎，這輪調整已套用至 `src/`。

## 設計與行為

- 統一中性色、系統字體、分隔線、圓角與藍色操作重點。家族標題與姓氏印記保留原有特色；世代色帶、各類關係線的顏色與意義不變。
- 工具列使用輕量材質；清單、人物詳情與表單維持實色閱讀底。主要動作、次要動作、目前選取與鍵盤焦點有各自的清楚狀態。
- 成員狀態改為分段控制外觀；正在查看的人物同步標示於清單。搜尋無結果時可直接清除搜尋與篩選。
- 桌面可用 Ctrl／⌘ K 開啟成員搜尋；搜尋框按 ↓ 進入結果，↑／↓ 瀏覽、Home／End 到首尾、Enter 開啟人物。每位成員只有一個循序 Tab 停靠點。快捷鍵不攔截輸入欄位、組字或進行中的 modal 任務。
- 更多功能依「檢視 → 成員管理 → 備份、同步與輸出 → 族譜設定」排列。搜尋後清除關鍵字會恢復先前各分組的展開狀態；零結果提供明確回復入口。可用方向鍵從搜尋框進入可用的功能。
- 桌面更多功能直接聚焦搜尋；手機先聚焦關閉按鈕，讓使用者先瀏覽功能，避免開啟選單就叫出鍵盤。
- 補上 viewport safe area、Android 鍵盤縮放提示、搜尋鍵盤語意與手機輸入字級。沿用既有草稿、取消保護、復原、儲存、關係查詢與可中斷動態機制。
- 減少透明度時使用實色工具列；高對比與 forced colors 下補上選取邊界。沒有新增動畫套件或外部字體。

設計參考：[Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[Apple Search fields](https://developer.apple.com/design/human-interface-guidelines/search-fields)，以及專案 `apple-design`／`mobile-native` 技能。這是針對本專案的設計實作，不代表 Apple 認證或全面無障礙認證。

## 驗證方式

使用 Windows Node v24.22.1、Edge Playwright。所有資料操作使用暫存 fixture 複本或隔離的瀏覽器儲存空間。

新增 `tests/browser-apple-workflows.cjs`：API／靜態模式各測 1440×900、1024×768、390×844、844×390、320×740，共 10 組。涵蓋搜尋回復、鍵盤導覽、人物選取、進行中表單的快捷鍵保護、選單搜尋與展開狀態恢復、焦點返回、工具列溢位、JS 錯誤與資料保持。

四組新配色以 sRGB 相對亮度公式計算：主要操作藍／白 5.57:1、次要文字／白 5.77:1、選取文字／淡藍底 4.97:1、查詢說明／淡藍底 6.38:1。這只涵蓋這四組實色配對，不能推及透明材質、全部既有元件或整站無障礙符合性。

測試先等待 dev server 完成 JSON canonicalization，再固定暫存檔的位元組內容，逐流程確認瀏覽操作不寫入變更；另外核對原始 fixture 未變。

實際應用驗收仍使用專案既有測試。`harness/config.json` 是尚未設定的範本，未將其自我測試當成應用驗收。這輪執行選定的 UI／儲存／地圖回歸，並非全部 54 suites 的全量驗收。

執行命令：

```powershell
$env:PLAYWRIGHT_MODULE='C:\Users\bluef\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules\playwright'
$env:PHASE5_SUITE_FILTER='^(unit|browser-(apple-workflows|ui-improvements|action-layout|button-layout|motion|canvas-motion|phase[1-5]|map-workspace|static|static-storage-errors)\.cjs|build|release-package)$'
$env:PHASE5_OUTPUT_DIR='.codebase-memory/phase5-results/apple-ui-20261103'
node tests/run-phase5.cjs
```

逐項 log 與總報告：`.codebase-memory/phase5-results/apple-ui-20261103/report.json`。新流程報告與桌面／手機截圖位於同目錄的 `apple-ui/`。

初次執行保留了兩項失敗：`browser-phase1.cjs` 未展開預設收合的差異篩選區；`browser-static.cjs` 假設人物選項只有姓名，且沿用舊的「所有關係」篩選文字。兩者在修改前的 `15c0bc3376d1c602d1d566edb581036aa17d841a` 版本均重現原始失敗，證據在 `.codebase-memory/phase5-results/apple-ui-baseline/`。本輪只修正測試操作與人物識別方式，保留全部原有內容、持久化、取消、關係及零 API 請求檢查；沒有為測試改動正式匯入或資料邏輯。

後續驗證另存於 `apple-ui-20261103-followup/`、`apple-ui-20261103-static-final/` 與 `apple-ui-20261103-static-verified/`，原始失敗報告未覆寫。正式程式在這些重跑期間沒有修改。

最終彙整：`.codebase-memory/phase5-results/apple-ui-20261103/verification-summary.json`，逐項指向實際通過的來源 log。**17 組選定驗證最終通過**，其中包含 **284 項 Node 資料測試**、14 組瀏覽器 suites、建置與發布包檢查。原始 fixture 未變，各次執行期間正式程式一致；新流程的 API／靜態 10 組情境均通過。這不是全量 54 suites，也未完成實機／真實授權驗收。

## 限制

視窗尺寸模擬不等同實體觸控、軟體鍵盤與瀏海安全區驗收。尚未執行實體 iPhone／Android、VoiceOver、真實 Google OAuth／Drive，以及全面對比值／文字放大稽核。未部署或發布網站。
